# TECHNICAL DESIGN DOCUMENT

## 1. Overview
Four refinements on top of the wave just shipped in commit `b087a60` (click-to-enlarge
images, taskbar icon AppUserModelID bump, icon transparency redesign) — all direct user
feedback after trying the shipped feature, not new scope. This wave is explicitly `v0.9.2`.

1. **Preview dialog reads as "not actually bigger."** `ImagePreviewDialog` only scales images
   *down* when they exceed the target box; a small pasted image (already downscaled to chat/
   description width at paste time) shows at native size in its own dialog, which doesn't feel
   like an enlargement. Fix: always scale to the target box, up or down.
2. **Confirmed real bug, not a perception issue: click-to-enlarge does nothing on an
   already-posted diary/chat entry ("LOG"), while it works while composing ("ENTRADA").**
   Root cause, empirically reproduced: `LogEntryWidget.content_label`'s
   `setTextInteractionFlags(Qt.TextSelectableByMouse)` *replaces* the interaction flag set
   (it doesn't add to whatever QLabel defaults to), stripping out
   `Qt.TextInteractionFlag.LinksAccessibleByMouse` — the flag Qt needs to fire
   `linkActivated` at all. A live repro confirmed: the exact same `QLabel` setup with only
   `TextSelectableByMouse` never fires `linkActivated` on an image-anchor click;
   `TextSelectableByMouse | LinksAccessibleByMouse` fires it every time. The existing test
   `test_log_entry_widget_routes_image_link_to_preview` (added last wave) passed anyway
   because it called `_on_content_link_activated(...)` directly, never exercising the actual
   click → `linkActivated` path — that gap must close this wave.
3. **Description-pasted images can overflow if the dialog is later resized smaller.**
   `self.desc_input = MarkdownTextEdit()` never sets `image_width_provider`, so
   `_insert_image` falls back to the editor's viewport width *at paste time*, embedded as a
   fixed pixel width in the stored HTML. User's explicit ask: same default size as chat images.
4. **Icon still showed a grayish halo instead of a crisp, fully-transparent background
   (already fixed directly — not a Coder task, verify-only).** The previous threshold
   (whiteness 170–225) left much of the soft drop-shadow gradient partially opaque, since most
   background pixels actually sit in 195–225 per a fresh histogram of the *true* original
   (pulled from git history at `8987982`, since `ekin_icon.png` had already been overwritten
   once). Regenerated with a tighter threshold (140–165). An opacity-mask visualization
   confirmed what looked like a stray white shape in the previous result is actually not
   background at all — it's the badge's own intentional torn/peeled-corner silhouette,
   correctly kept opaque; the mask shows one clean connected badge shape, crisp edge, fully
   transparent everywhere else (outer-edge alpha now uniformly 0, was 0–97). `ekin_icon.png`/
   `.ico` (7 sizes) already overwritten on disk; `git status` shows both modified.

  ```python
  def test_log_entry_widget_real_click_on_posted_image_opens_preview(qapp, monkeypatch):
      """Regresión: setTextInteractionFlags(Qt.TextSelectableByMouse) A SOLAS anulaba
      LinksAccessibleByMouse y linkActivated nunca se disparaba con un clic real, aunque
      _on_content_link_activated (probado por separado más abajo) funcionase perfectamente
      si se llamaba a mano. Este test dispara un QMouseEvent real para que un futuro cambio
      de flags no pueda romper esto en silencio otra vez."""
      calls = []
      monkeypatch.setattr(log_entry_module, "show_image_preview", lambda uri, parent=None: calls.append(uri))
      log_data = {
          "id": 1,
          "content": f'<a href="{_TINY_PNG_DATA_URI}"><img src="{_TINY_PNG_DATA_URI}" width="80" height="80"/></a>',
          "created_at": "2026-08-12 10:00:00",
      }

      widget = LogEntryWidget(log_data, lambda *a: None, lambda *a: None)
      widget.show()
      qapp.processEvents()

      pos = QPoint(20, 20)
      press = QMouseEvent(QEvent.Type.MouseButtonPress, pos, Qt.LeftButton, Qt.LeftButton, Qt.NoModifier)
      release = QMouseEvent(QEvent.Type.MouseButtonRelease, pos, Qt.LeftButton, Qt.LeftButton, Qt.NoModifier)
      qapp.sendEvent(widget.content_label, press)
      qapp.sendEvent(widget.content_label, release)
      qapp.processEvents()

      assert calls == [_TINY_PNG_DATA_URI]
  ```
  `content` is deliberately *only* the image anchor (no surrounding text) with an explicit

  top-left and a click at `(20, 20)` reliably lands inside it — no fragile text-layout geometry
  involved. `QPoint`, `QMouseEvent`, `QEvent` are already imported in this test file from the
  previous wave.
